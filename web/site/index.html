Nullraum ist ein Chat für geschlossene Räume. Du erstellst einen Raum und bekommst einen Code. Den gibst du weiter, wie du willst: auf Papier, persönlich oder per Messenger. Wer den Code hat, kann anklopfen. Hinein kommt nur, wen du bestätigst. Texte, Bilder, Videos und Sprachnachrichten sind dabei post-quantum Ende-zu-Ende verschlüsselt.

So funktioniert's

Vom Zettel zum verschlüsselten Raum
in vier Schritten.

  1. 01

    Raum erstellen

    Dein Gerät erzeugt einen zufälligen Code mit 8 Blöcken zu je 4 Zeichen, einen zufälligen Raumschlüssel und deine post-quantum Schlüsselpaare. Auf Wunsch kommen ein Passwort, ein Zweitschlüssel oder drei Sicherheitsfragen dazu.

  2. 02

    Code weitergeben

    Schreib den Code auf Papier, druck ihn aus oder schick ihn über einen Messenger. Du entscheidest, wer ihn bekommt. Verwechselbare Zeichen wie O/0 und I/1 sind ausgeschlossen, und eine Prüfsumme erkennt Tippfehler.

  3. 03

    Anklopfen & bestätigen

    Wer den Code eingibt, klopft an. Du als Initiator siehst Name und Sicherheitsnummer und klickst auf Aufnehmen. Erst dann bekommt die Person den Raumschlüssel, verschlüsselt mit ML-KEM-768 + X25519 nur für ihr Gerät.

  4. 04

    Sicher chatten

    Jede Nachricht wird mit dem Raumschlüssel verschlüsselt und mit ML-DSA-65 signiert. Entfernst du jemanden, wird der Schlüssel sofort gewechselt. Die Person kann danach nichts mehr mitlesen.

⚛︎

Post-Quantum von Anfang an

Der Schlüsselaustausch nutzt den hybriden HPKE-KEM aus ML-KEM-768 (FIPS 203) und X25519. Ein Angreifer müsste beide Verfahren brechen. Damit hilft auch „heute mitschneiden, später mit Quantencomputer entschlüsseln“ nicht. Signaturen nutzen ML-DSA-65 (FIPS 204).

Nachricht→ML-DSA-65 Signatur→XChaCha20-Poly1305→Padding→Relay
✓

Initiator bestätigt jeden

Der Code allein reicht nicht. Jede Beitrittsanfrage muss aktiv angenommen werden, und eine Sicherheitsnummer deckt Man-in-the-Middle-Angriffe auf.

🔐

Zweite Schutzschicht

Optional sichern ein Passwort, ein separater Zweitschlüssel oder drei Sicherheitsfragen den Raum zusätzlich ab. Das Geheimnis wird mit Argon2id gehärtet und fließt in alle Schlüssel ein.

🎙

Bilder, Videos, Sprachnachrichten

Bis 50 MB pro Datei. Jede Datei bekommt einen eigenen Schlüssel. Bei Fotos werden Metadaten wie der GPS-Standort vor dem Senden entfernt.

⧉

Redundant, aber nur im Raum lesbar

Jedes Mitglied hält eine verschlüsselte Kopie des Verlaufs. Fehlt einem Gerät etwas, liefern die anderen es Peer-to-Peer nach. Lokal liegen nur Chiffretexte, und ohne Code ist nichts lesbar.

↻

Schlüsselwechsel & Rauswurf

Wer entfernt wird oder geht, bekommt den nächsten Schlüssel nicht mehr. Neue Mitglieder sehen ältere Nachrichten nur, wenn du das erlaubst.

⌁

Blindes Relay

Der Server leitet nur Rauschen weiter. Er kennt weder Codes noch Namen, Raumnamen oder Schlüssel, speichert nichts auf der Festplatte und schreibt keine IP-Logs.

⏻

Panik-Knopf

Ein Klick löscht alle Räume, Schlüssel und Medien vom Gerät. Der Initiator kann einen Raum außerdem für alle schließen. Dann löschen alle Geräte ihre Kopie.

Sicherheit

Was der Server sieht und was nicht.

Nullraum ist auf ein nicht vertrauenswürdiges Relay ausgelegt. Selbst wenn der Server kompromittiert ist, bleiben Inhalte, Namen und Codes geheim.

Relay sieht

  • eine zufällig wirkende Raum-ID (Hash, aus dem Code abgeleitet)
  • wie viele Verbindungen in einem Raum sind
  • Zeitpunkt und gepolsterte Größe verschlüsselter Pakete
  • IP-Adressen der Verbindungen (nicht geloggt; nutze VPN/Tor, wenn das wichtig ist)

Relay sieht nie

  • den Raumcode, das Passwort, den Zweitschlüssel oder die Antworten
  • Nachrichten, Bilder, Videos, Sprachnachrichten
  • Namen der Mitglieder und des Raums
  • wer welche Nachricht geschrieben hat
  • irgendeinen Schlüssel

Ehrlich gesagt: Was Nullraum nicht kann

  • Kompromittierte Geräte. Schadsoftware auf einem Gerät oder ein Screenshot liest mit. Keine Verschlüsselung der Welt hilft dagegen.
  • Vertrauen in den App-Code. Öffnest du die App über einen fremden Server, könnte dessen Betreiber manipulierten Code ausliefern. Am sichersten ist es, den Server selbst zu betreiben oder nullraum client lokal zu starten. Dann kommt der Code von deinem eigenen Rechner.
  • Metadaten. Wann wie viel gesendet wird, ist für das Relay sichtbar. IP-Adressen werden nicht geloggt, sind technisch aber vorhanden.
  • Forward Secrecy pro Nachricht. Der Raumschlüssel wechselt bei jedem Rauswurf, bei jeder Aufnahme (wenn neue Mitglieder den Verlauf nicht sehen dürfen) und auf Knopfdruck, aber nicht bei jeder Nachricht.
  • Kein Audit. Das Projekt ist neu und noch nicht unabhängig geprüft. Reviews sind willkommen.
Installation

In einer Minute startklar.

Einer betreibt das Relay, zum Beispiel auf einem kleinen Server, NAS oder Raspberry Pi. Alle anderen öffnen nur die Adresse im Browser.

Relay und App mit einem Befehl:

docker run -d --name nullraum -p 8080:8080 --read-only ghcr.io/maliceatthepalace/nullraum:latest

Mit automatischem HTTPS über Caddy (empfohlen, für Sprachnachrichten nötig):

git clone https://github.com/maliceatthepalace/nullraum && cd nullraum
NULLRAUM_DOMAIN=chat.example.org docker compose up -d
curl -L -o nullraum https://github.com/maliceatthepalace/nullraum/releases/latest/download/nullraum-linux-amd64
chmod +x nullraum
./nullraum serve -addr :8080        # Relay + App
./nullraum serve -self-signed       # HTTPS im LAN

Auf ARM (z. B. Raspberry Pi) nullraum-linux-arm64 verwenden.

curl -L -o nullraum https://github.com/maliceatthepalace/nullraum/releases/latest/download/nullraum-darwin-arm64
chmod +x nullraum && xattr -d com.apple.quarantine nullraum
./nullraum client -relay https://chat.example.org

Für Intel-Macs nullraum-darwin-amd64 verwenden. client liefert die App lokal aus und verbindet sich nur mit dem Relay.

Invoke-WebRequest -OutFile nullraum.exe https://github.com/maliceatthepalace/nullraum/releases/latest/download/nullraum-windows-amd64.exe
.\nullraum.exe client -relay https://chat.example.org

Ein Doppelklick auf nullraum.exe startet ein lokales Relay und öffnet den Browser.

git clone https://github.com/maliceatthepalace/nullraum && cd nullraum
make            # baut WASM-Kryptokern + Binary (Go ≥ 1.26)
./bin/nullraum serve
FAQ

Häufige Fragen

Was passiert, wenn jemand Fremdes meinen Code findet?

Die Person kann anklopfen, mehr nicht. Du siehst die Anfrage und lehnst sie ab. Ist der Raum zusätzlich geschützt, scheitert sie schon vorher, und nach drei Fehlversuchen wird sie ignoriert. Erstelle im Zweifel einfach einen neuen Raum.

Muss der Initiator online sein?

Zum Aufnehmen neuer Mitglieder ja, denn nur sein Gerät kann den Raumschlüssel an Neue verteilen. Zum Chatten nicht. Nachrichten an Offline-Mitglieder hält das Relay verschlüsselt bis zu 72 Stunden im Arbeitsspeicher, und andere Mitglieder liefern fehlende Nachrichten Peer-to-Peer nach.

Wo werden meine Nachrichten gespeichert?

Verschlüsselt im Browser jedes Mitglieds (IndexedDB). Ohne Code, und gegebenenfalls ohne Passwort oder Antworten, sind sie nicht lesbar. Auf dem Server liegt nichts dauerhaft.

Ich habe meinen Code verloren. Kann man ihn wiederherstellen?

Nein, und das ist Absicht. Der Code wird nirgends gespeichert. Bitte ein anderes Mitglied, ihn dir auf demselben Weg noch einmal zu geben. Dein Gerät öffnet den Raum dann wieder.

Warum „post-quantum“?

Künftige Quantencomputer könnten heutige Public-Key-Verfahren wie RSA oder klassisches Diffie-Hellman brechen. Wer heute verschlüsselten Verkehr mitschneidet, könnte ihn später entschlüsseln. Nullraum nutzt dafür die 2024 standardisierten Verfahren ML-KEM und ML-DSA, kombiniert mit X25519 als klassischer Absicherung.

Ist Nullraum ein Ersatz für Signal?

Nullraum hat einen anderen Zweck: kurzlebige oder geschlossene Räume ohne Konto und ohne Telefonnummer, die du selbst hostest. Signal ist deutlich länger erprobt und bietet Forward Secrecy pro Nachricht. Wähle, was zu deinem Bedrohungsmodell passt.
